# 结构、通信与记录格式

## 模块职责

| 模块 | 负责什么 | 不应负责什么 |
| --- | --- | --- |
| `game.core` | 不可变卡牌定义、卡牌实例、状态深复制、完整规则、预览、确定性洗牌 | JavaFX 控件、Socket、窗口、网络身份 |
| `game.net` | UTF-8 JSON 分帧、客户端连接、可见视图、记录序列化 | 决定伤害与胜负 |
| `game.server` | 连接会话、双人房间、准备、命令授权、串行执行、定向同步 | 信任客户端的费用、伤害或卡牌定义 |
| `game.client` | 本地/联网模式、选择卡牌目标、预览与确认、信息显示、导出 | 在联网模式自行裁定规则结果 |

选择单 Maven 工程、按包分层，是为了便于课程项目运行与讲解。规则对象不引用 JavaFX，测试和服务器可在没有图形界面的环境运行；只在客户端界面层处理绘制与用户交互。

卡牌定义与实例分离：定义保存稳定 ID、名称、类型、阵营和基础数值；手牌中的 `Card` 带独立 `instanceId`；场上的 `Unit` 额外持有当前生命、登场回合与焦虑到期。资源卡通过类型单独处理，0 生命不等于普通单位死亡。

`GameEngine` 持有真正的状态，外部获得深复制快照。合法操作包含实例 ID、目标列、牺牲列与预期状态版本。规则校验结束后才改变状态，避免哀悼一半成功一半失败。重复点击或过期版本会被拒绝。服务端在同房间重开时也延续版本序列，避免上一局延迟到达的操作误用于新局。

## 联网设计

TCP 采用 UTF-8 **一行一个 JSON 对象**，用换行作为消息边界。服务端输入行最大为 16,384 字节，在读取时限制长度；不接收 Java 序列化对象。房间内操作串行执行，网络读写不占 JavaFX 主线程；界面变更回到 JavaFX 线程。

服务器支持 `create`、`join`、`ready`、`play`、`end`、`preview`、`export` 和心跳请求。创建方占第一席努斯，加入方占第二席逻各斯；先手单独配置。客户端不能通过消息里的自报阵营切换身份，服务器从连接会话取得所属席位。

同步的 `GameView` 按玩家单独生成：自己完整手牌、对手手牌数、双方牌库数量、场上单位、公开资源与日志。普通抽牌日志不含牌名，实际烧牌进入公开弃牌区后才记录牌名；预览过滤未发生的抽牌和烧牌。服务端不在对局中发送种子、初始牌序、对手手牌或可恢复隐藏信息的完整状态。

服务器有房间、连接、请求速率、输入长度与发送队列边界。TCP 断开、读超时或通信错误按断线处理。当前策略是结束正在进行的对局，不保留可恢复的会话；新会话只能开始新局。这一版本面向课程本地/局域网演示，没有账户认证、公网防护或持久化数据库。

## Java 记录格式 3

完整记录顶层字段：

| 字段 | 意义 |
| --- | --- |
| `format` | `心理天平Java试玩记录` |
| `version` | `3`，表示 Java 数据结构版本 |
| `balanceVersion` | `prototype-build07`，表示采用的卡牌数值基线 |
| `exported` | UTC ISO 时间 |
| `notes` | 导出者填写的试玩笔记 |
| `cardDefinitions` | 本次使用的卡牌定义 |
| `game` | 完整 `MatchState` 快照 |

`game` 包含规则、卡池、先手、名字、种子、初始牌序、双方所有牌区与资源、当前行动方、天平、状态版本、终局原因、事件和合法操作列表。`winner=null` 在未结束与平局都可能出现，Gson 序列化时会省略该空字段；读取时缺失等同于 null，必须同时检查 `over` 和 `reason`。`actions` 中每条操作记录类型、阵营、实例 ID、目标列、牺牲列、当时版本和满槽受阻勾选。`initialVersion` 为本局起始版本：同机通常为0，联网重开可大于0；程序重放时使用七参构造传入该值，再依次执行 actions。断线终局是服务端事件，不是玩家行动，重放到最后需单独应用 disconnect。

完整记录可能暴露所有历史手牌与牌序：本地同机模式可以导出；联网必须等对局结束才允许。仍在进行的网络局导出的是**视角记录**：

```json
{
  "format": "心理天平Java视角记录",
  "version": 3,
  "complete": false,
  "exported": "UTC ISO 时间",
  "notes": "测试笔记",
  "view": "此处实际为当前玩家可见状态对象"
}
```

上例仅解释结构，不是可直接导入的样本。视角记录没有足够数据重建双方完整局面。

## 与网页旧记录的关系

网页记录格式是 `心理天平试玩记录` v1/v2；Java 格式 3 新增实例身份、状态版本、独立操作列表与隐私视图，字段名称和结构不完全相同。当前没有旧 JSON 导入按钮，也没有 v1/v2→v3 自动迁移器。不能通过改一个 `version` 字段使它兼容。

规则测试可以用固定初始牌序与同一合法操作序列检查确定性，也可以将交接包记录转换为测试输入；这不等于已向用户提供存档导入或继续旧局功能。迁移范围与实际对照过的记录，以验证说明和测试源码为准。

以后添加读档，需要先验证版本、卡池、牌张守恒、阵营、实例唯一性、牌区互斥、合法回合与资源范围，再在新的状态副本上恢复。不能把任意网络 JSON 直接替换当前引擎状态。

## 后续扩展入口

卡牌数据保存在 `src/main/resources/cards.tsv`，新增效果同时需要定义类型处理与规则测试。平衡改值应建立新版本，避免用新数值冒充原型 build07 的重现。当前无最终美术；文字卡面集中在客户端实现，可按稳定英文卡牌 ID 接入素材，不应把图像对象放入规则核心。
