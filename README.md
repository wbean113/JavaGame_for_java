# 心理天平 · Java 双人卡牌游戏

Java 21 + JavaFX 桌面客户端，纯 Java 规则核心，TCP + JSON 权威服务器。以交接包的 **G 规则 / build07 卡牌数值**为默认，保留 **F 规则**对照。工程独立于原 IDEA 学习工程，原始资料包没有被改写。

`base` 表示“不含法术”，G 的 base 仍有死亡回费单位。F/G 都有后手补偿资源卡。此版本验证规则与软件行为，不代表已经证明阵营平衡。

## 1. 环境与构建

需要 **Windows、JDK 21**；首次构建需要网络下载 Maven 依赖。JavaFX、Gson 和 JUnit 的版本在 `pom.xml` 中固定，不必手动配置 JavaFX SDK。当前提供源码、JAR 和依赖目录的构建方式，**没有捆绑 JDK 的免安装发行包**。

在项目目录打开终端：

```powershell
.\build.cmd
```

默认执行编译、自动测试和打包。成功后得到：

```text
target/psychological-balance-1.0.0.jar
target/lib/                         # 启动所需全部运行时依赖
target/surefire-reports/            # 自动测试报告
```

脚本先查 `JAVA21_HOME`、`JAVA_HOME`，再查常见 JDK 安装目录与 PATH，只接受 JDK 21。旧 JDK 8 不会被卸载或覆盖。可在当前 PowerShell 窗口指定其他安装位置：

```powershell
$env:JAVA21_HOME = 'D:\Software\jdk-21'
.\build.cmd
```

Maven 优先使用 PATH 或 IntelliJ IDEA 自带的版本；找不到时下载固定的 Apache Maven 3.9.9 到项目 `.tools/` 并校验官方 SHA-512。依赖缓存固定为项目 `.m2/`，脚本不修改全局环境变量、用户 Maven 配置或其他 Java 工程。

```powershell
.\build.cmd -Clean          # 清理 target 后重新构建并运行测试
.\build.cmd -UiTests        # 额外运行真实JavaFX窗口测试，需要可用的桌面
.\build.cmd -SkipTests      # 明确跳过测试；不能作为测试通过的证据
```

不使用脚本时，先让当前终端使用 JDK 21，再执行：

```powershell
mvn -B -ntp "-Dmaven.repo.local=$PWD\.m2" clean package
```

## 2. 同机双人试玩

```powershell
.\run-client.cmd
```

在顶部“开局与联机设置”中的“新局配置”选择规则 F/G、卡池“不含法术”/“含法术”（对应 base/spells）与先手，在“同机双人”一行填写双方名字和种子，点击“开始同机对局”。同一种子、配置和相同合法操作可重复相同结果。对局开始后设置区自动收起，点击标题可展开设置新局；确认和结束回合按钮固定在底部。

一局的基本操作：

1. 点击“我已接手 · 查看手牌”后查看自己的手牌；同机换人时自动遮住新行动方的手牌，交接电脑后再解除遮罩。
2. 选一张手牌，再选择目标槽位。普通单位与资源卡选己方空槽；焦虑选敌方普通单位；哀悼先选己方在场普通单位或资源卡作牺牲，再选敌方普通单位。
3. 查看出牌预览。它模拟“打出所选牌后立即结束回合”，继续出其他牌会改变结果。
4. 点击确认出牌，才会扣费并执行。确认出牌和结束回合是两个操作。
5. 可以继续出牌，或点击“结束回合 · 结算战斗”；此时自动按左、中、右顺序战斗、结算资源并交给对方。也可先点击“预览直接结束回合”。
6. 天平到达阈值或双方各完成 30 个回合时显示终局。在右侧“试玩笔记”填写反馈，点击“导出 JSON 记录”选择保存位置。

界面展示当前生命/最大生命、有效攻击、登场限制、焦虑、冲动来源、天平与事件日志。自己回合中费用不足的牌仍可点击，会显示“需要几费、当前几费”的具体原因。满槽受阻勾选仅用于试玩统计，不改变规则；右上角“规则帮助”可随时查看说明。

## 3. 本机两个客户端联机

先开服务端，再在两个独立窗口启动客户端：

```powershell
.\run-server.cmd
.\run-client.cmd
.\run-client.cmd
```

服务端占用当前终端，请分别在新终端运行客户端命令，或双击两个 `run-client.cmd`。

1. 两个客户端顶部“局域网”一行中，主机填 `127.0.0.1`，端口填 `23456`。
2. 第一位玩家填写名字，选择规则、卡池和先手，点击“连接并建房”；当前实现第一席为努斯。
3. 将界面显示的六位房间码交给第二位玩家；第二位玩家填写自己的名字和房间码后点击“连接并加入”，为逻各斯。
4. 两人都点击“准备 / 再来一局”，服务器开始对局。只有行动方能够出牌或结束回合。
5. 终局后，双方再次点击“准备 / 再来一局”可开始同配置新局。每一局由服务器生成新的私有洗牌种子，顶部同机种子输入框不会影响联网洗牌。

服务器默认监听 `0.0.0.0:23456`。需要换端口时运行：

```powershell
.\run-server.cmd -Port 24567
```

客户端也应使用对应端口。服务器终端按 `Ctrl+C` 停止。

## 4. 两台电脑的局域网连接

1. 两台电脑连接同一个可互相访问的局域网；每台都安装 JDK 21。将本项目复制过去后构建，或复制已构建项目的启动脚本、`target` JAR 和整个 `target/lib`。
2. 任选一台作为房主电脑，运行 `run-server.cmd`。服务端可以和房主客户端运行在同一台电脑。
3. 在房主电脑运行 `ipconfig`，找到正在使用的网卡 IPv4 地址，例如 `192.168.1.23`。
4. 两个客户端都填写该 IPv4 和端口 `23456`，再按创建房间、加入房间、双方准备的步骤开始。
5. 若系统提示防火墙权限，允许 Java 在所使用的可信局域网接收入站连接；确认该 TCP 端口可达。校园网或访客 Wi-Fi 的客户端隔离可能阻止电脑之间互连。

连接失败时可以在另一台 Windows 电脑执行 `Test-NetConnection 192.168.1.23 -Port 23456`。地址应换成实际房主 IPv4。`127.0.0.1` 只指向当前电脑，不能用它连接另一台电脑。

本机联调与跨电脑局域网实测是两项不同验证，实际完成情况见[验证记录](docs/验证记录.md)。公网部署、路由器端口转发、账户系统和 TLS 加密未作为本次交付目标。

## 5. 关键规则

双方各有 20 张固定牌组与三列战场。天平初始为 0，努斯向正方向、逻各斯向负方向推动：到 `+12` 努斯胜，到 `-12` 逻各斯胜。保留实际超出值。双方各完成 30 回合仍未达到阈值时，按天平正负判胜，0 为平局。

每人开局抽 3 张，自己的每个回合开始再抽 1 张。后手第一次正常抽牌后，额外得到一张资源卡。手牌上限为 10，第 11 张入弃牌区；牌库耗尽不产生疲劳伤害。

基础冲动每个自己的回合增长 1，最高 10。上回合最多保留 2 点储备，再依次计入资源卡待用和亡语待用，总可用最多 10；超出部分消失。可用冲动与基础上限在界面中分别显示。

结束回合时，己方普通单位逐列攻击。有对位普通单位时双方同时造成伤害，残血保留，过量伤害不会推动天平。没有对位时，只有在**更早的己方回合**登场的单位才能推动天平；新单位可立即交战。任一次天平改变达到阈值，立即停止后续结算。

| 特殊牌 | 效果 |
| --- | --- |
| 焦虑（努斯，2 费） | 敌方普通单位攻击减 2，最低 0；到目标方下个回合战斗后恢复，重复施放刷新而不叠加。 |
| 哀悼（逻各斯，2 费） | 牺牲己方一张在场牌，对敌方普通单位造成 3 点法术伤害；两个目标必须都合法才执行。 |
| 空虚 / 祈盼（0 费资源卡） | 占己方槽位，己方回合战斗后正常离场，下个己方回合可用冲动 +1；提前被牺牲没有收益。 |
| 余悸 / 释然（G，2 费，1 攻 3 血） | 在场死亡一次，所属方下个回合待用冲动 +1；弃手牌不触发。 |

G 用余悸/释然替换 F 的烦躁/清明；不增加牌组张数。详细顺序、完整卡池和界面中数字的解释见[规则说明](docs/规则说明.md)。

## 6. 试玩记录、隐私与断线

- 本地完整导出与联网终局完整导出使用 `format=心理天平Java试玩记录`、`version=3`，记录配置、初始牌序、实例 ID、合法操作、事件和笔记。
- 联网对局进行中只允许导出当前玩家的可见视角，使用 `format=心理天平Java视角记录`、`version=3`、`complete=false`。不能用它还原双方完整牌库。
- 网络同步只包含自己的手牌、对手手牌数量和公开场面。种子和完整初始牌序保留在服务端，对局中不发送给客户端。
- 当前没有记录导入、读档继续或旧网页 v1/v2 导入界面。格式版本 3 是独立的 Java 格式，不等同于旧网页格式升级后直接兼容。见[结构与记录格式](docs/结构与记录格式.md)。
- 任一玩家断线会终止当前对局；重新连接不会恢复旧会话或续局。重新入房后双方准备开始新局。需要保留结果时，在仍可操作的客户端导出记录。

## 7. 工程结构与答辩入口

```text
src/main/java/game/core/       # 卡牌定义、状态、规则引擎、确定性洗牌
src/main/java/game/net/        # JSON分帧、客户端连接、可见视图、记录导出
src/main/java/game/server/     # 双人房间、准备、会话身份、串行执行与广播
src/main/java/game/client/     # JavaFX界面、选目标、预览、规则帮助
src/main/resources/cards.tsv   # 卡牌数据，使用原型数值
src/test/                     # 规则、重放与网络行为测试
docs/                         # 规则、架构、验证说明
build.cmd / build.ps1         # 测试并打包
run-client.cmd / .ps1         # 客户端入口 game.client.Launcher
run-server.cmd / .ps1         # 服务器入口 game.server.GameServer
```

答辩可从三个问题展开：规则为什么独立于 JavaFX；服务器为什么重新校验每一步行动；同一个规则引擎如何服务本地对局、联网对局和预览。项目没有使用 FXGL/KryoNet：三列回合制操作不需要实时物理引擎，JDK Socket + 明确的 JSON 协议足以表达动作，便于阅读、测试和解释。

## 8. 常见问题与范围

- **提示找不到 JDK 21**：检查安装，设置当前终端的 `JAVA21_HOME`。只装 JRE 或仅有 JDK 8 不能构建本项目。
- **PowerShell 不允许运行脚本**：使用 `.cmd` 入口；它仅为该进程传入 `ExecutionPolicy Bypass`，不修改系统策略。如果设备由学校策略限制，按管理员允许的方式运行。
- **首次下载失败**：保留命令窗口中的具体 Maven/网络错误，检查网络、代理或仓库连接，再重新运行构建。离线机器必须提前取得 JDK、已构建 JAR 与全部依赖，不能凭一个 JAR 自动运行。
- **提示主类或依赖缺失**：先完整执行 `build.cmd`，确保 `target/lib` 与 JAR 同时存在。更改源码后需要重新构建。
- **端口被占用**：停止占用程序或用 `-Port` 换一个端口，两端配置保持一致。
- **clean 无法删除 JAR**：先关闭本项目正在运行的客户端和服务器，再重新构建；Windows 会锁定运行中的 JAR。
- **JavaFX unnamed module 提示**：当前用 classpath 运行，会产生此配置警告；本机已验证客户端能正常启动。它不表示编译失败。
- **手牌变灰/不能确认**：查看具体提示；可能是非自己的回合、费用不足、己方槽满或目标不合法。资源卡也要占一个空槽。
